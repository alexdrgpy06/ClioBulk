## 2024-04-23 - Bypassing React renders for high-frequency progress updates
**Learning:** In Zustand v4 setups where `subscribeWithSelector` is not used during store creation, `useStore.subscribe` listens to the entire state object. To prevent UI desyncs or redundant DOM updates when bypassing React renders for specific property changes (e.g., `progress`), explicitly synchronize the initial state by reading `useStore.getState()` in `useEffect` and manually compare current/previous state within the subscription callback. Furthermore, the component's `useStore` hook must NOT subscribe to the high-frequency state property itself, as this would still trigger unnecessary React re-renders and defeat the optimization.
**Action:** When optimizing progress bars or similar high-frequency UI elements, use `useRef` for direct DOM manipulation and `useStore.subscribe(callback)` to bypass React's render cycle, while carefully ensuring the component only subscribes to low-frequency states (like `processing`) via the main `useStore` hook.
