## 2024-05-11 - Optimize file lookup in process-progress event
**Learning:** In ClioBulk, the `process-progress` event listener inside `src/App.jsx` was using an $O(N)$ `Array.find()` search over `files` to resolve file IDs by path for every high-frequency progress update from the backend. Since the list of files changes infrequently relative to these events, it's significantly more efficient to maintain a pre-computed $O(1)$ lookup dictionary (`fileIdsByPath`) in the Zustand store and use it during the hot path. Rebuilding a map during high-frequency events is worse than the array find, so the map must only be mutated when files are explicitly added, removed, or cleared.
**Action:** Always verify if an $O(N)$ lookup is on a hot path, and precompute an $O(1)$ map during the cold path (state updates) to avoid redundant computations.
