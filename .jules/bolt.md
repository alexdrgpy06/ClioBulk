## 2024-04-12 - Bypass React renders for high-frequency Zustand state updates
**Learning:** In Zustand v4 setups where `subscribeWithSelector` is not used during store creation, `useStore.subscribe` listens to the entire state object. When trying to bypass React renders for high-frequency state updates (like a progress bar) using `useStore.subscribe` and a `useRef`, the component's `useStore` hook must also explicitly stop subscribing to that high-frequency property. Otherwise, the hook will still trigger unnecessary re-renders, defeating the optimization. Additionally, because the subscription might be delayed, it's critical to explicitly synchronize the initial state by reading `useStore.getState()` inside the `useEffect` and manually comparing current/previous state within the subscription callback to prevent UI desyncs or redundant DOM updates.
**Action:** Always ensure that components bypassing renders for specific state properties are not also subscribing to those properties in their `useStore` hook. Always synchronize the initial state manually when using `useStore.subscribe` in a `useEffect` for DOM manipulation.
