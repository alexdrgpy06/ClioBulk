## 2024-05-18 - Manual state comparison in Zustand without subscribeWithSelector
**Learning:** When bypassing React renders for high-frequency state updates using `useStore.subscribe` and a `useRef` (e.g., for a progress bar), if the store was created without `subscribeWithSelector`, `useStore.subscribe` listens to the entire state object. To prevent redundant DOM updates, you must manually compare the current and previous state of the specific property (e.g., `state.progress !== prevState.progress`) within the subscription callback. Additionally, ensure the component's `useStore` hook does not subscribe to that high-frequency property, as this will trigger unnecessary re-renders and defeat the optimization.
**Action:** When setting up direct DOM manipulation subscriptions with standard Zustand stores, always include a manual state delta check (`state.prop !== prevState.prop`) in the callback and explicitly exclude the property from the `useStore(useShallow(...))` selection.
