## 2024-05-24 - DoS Vulnerability via Unhandled Panics in Async Tasks
**Vulnerability:** The `process_bulk` Tauri command used `unwrap()` on `Semaphore::acquire().await` and `tokio::task::spawn_blocking(...).await`. If either failed, it would panic the background thread or async task, potentially leading to a Denial of Service (DoS) for the entire application due to unhandled thread panics and leaving the UI stuck waiting for progress events that will never arrive.
**Learning:** In Tauri async commands, `unwrap()` should never be used on synchronization primitives (like `Semaphore`) or thread handles (`JoinHandle`) because errors during thread execution or resource acquisition should be handled gracefully, reported back to the frontend, and not crash the application. Shared resources (like `AppHandle`) needed for error reporting must be explicitly cloned before being moved into the closure so they remain available if the closure panics or fails.
**Prevention:** Avoid `unwrap()` in async and multithreaded Tauri commands. Use `match` or `?` to gracefully handle `Result` types. If a task fails, catch the error, log it, and emit a failure event to the frontend (e.g., `process-progress` with `success: false`) so the UI can recover. Ensure variables needed for error reporting are cloned before moving into closures.
