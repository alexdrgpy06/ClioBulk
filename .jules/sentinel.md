## 2024-03-30 - Prevent DoS via Unhandled Panics in Async Commands
**Vulnerability:** In `src-tauri/src/commands.rs`, the `process_bulk` function used `unwrap()` on `Semaphore::acquire().await` and `tokio::task::spawn_blocking().await` inside a `tokio::spawn` closure. If either of these operations failed, it would cause a panic, potentially crashing the entire application (Denial of Service).
**Learning:** Using `unwrap()` in async contexts, especially inside concurrent tasks or closures spawned to handle bulk operations, introduces significant DoS risks because unhandled panics will crash the process.
**Prevention:** Avoid `unwrap()` on shared resources or concurrent task spawns. Handle errors gracefully by using `match` or `if let Err` to log the failure, emit a failure event to the frontend (e.g., via `app.emit`), and exit the task safely without crashing the backend. Always clone necessary variables (like `AppHandle` or paths) before closures if they are needed for error reporting inside the `Err` branch.
